# DeepShield Backend Service

The **DeepShield Backend Service** is the central orchestration layer of the DeepShield platform. It is implemented in **Go** and is responsible for handling client requests, authentication, video upload processing, database operations, caching through video hashing, and communication with the machine learning inference service.

Rather than performing deepfake detection itself, this service coordinates the complete detection workflow and exposes REST APIs consumed by the frontend.

---

## Responsibilities

The backend service is responsible for:

- User registration and authentication
- JWT-based authorization
- Video upload handling
- Video hash generation
- Duplicate detection using cached analysis results
- PostgreSQL database interaction
- Communication with the Python ML service through gRPC
- Returning detection results and user history

## Environment Variables

Create a `.env` file in the `main_service` directory with the following variables:

```env
JWT_SECRET="your_jwt_secret"

DB_HOST="your_database_host"
DB_USER="your_database_user"
DB_PASSWORD="your_database_password"
DB_NAME="your_database_name"

GRPC_HOST="host"
```

### Variable Description

| Variable | Description |
|----------|-------------|
| `JWT_SECRET` | Secret key used to sign and verify JWT authentication tokens. |
| `DB_HOST` | PostgreSQL server hostname or IP address. |
| `DB_USER` | PostgreSQL username. |
| `DB_PASSWORD` | PostgreSQL user's password. |
| `DB_NAME` | Name of the PostgreSQL database. |
| `GRPC_HOST` | Address of the Python ML gRPC service (e.g., `localhost` or `ml_service` when using Docker Compose). |

## Request Workflow

### User Authentication

```
Client
   │
   ▼
Register/Login
   │
   ▼
Password Hashing
   │
   ▼
PostgreSQL
   │
   ▼
JWT Token
```

Authenticated endpoints require a valid JWT access token.

---

### Video Detection Workflow

```
Upload Video
      │
      ▼
Receive Multipart File
      │
      ▼
Save Video
      │
      ▼
Generate Video Hash
      │
      ▼
Check Existing Result
      │
 ┌────┴─────┐
 │          │
 │Found     │Not Found
 │          │
 ▼          ▼
Return     Send via gRPC
Cached        │
Result        ▼
         Python ML Service
                │
                ▼
      Prediction + Confidence
                │
                ▼
      Store in PostgreSQL
                │
                ▼
         Return Response
```

By hashing uploaded videos, identical files are analyzed only once. Cached predictions are returned immediately, reducing computation time and improving scalability.

## gRPC Communication

The backend communicates with the Python inference service using gRPC.

Service definition:

```protobuf
service Classify {
    rpc ClassifyVideo(ClassifyRequest)
        returns (ClassificationResult);
}
```

Request:

```protobuf
message ClassifyRequest {
    string video_path = 1;
}
```

Response:

```protobuf
message ClassificationResult {
    bool is_fake = 1;
    float confidence = 2;
}
```

Generated protobuf files are located in:

```
df_detect/
```

The original protocol definition resides in:

```
backend/proto/classify.proto
```

## Package Overview

### `controller`

Implements the REST API handlers and coordinates business logic.

Responsibilities include:

- User authentication
- Video upload processing
- Detection requests
- History retrieval
- Analytics

---

### `grpc_service`

Encapsulates communication with the Python ML service.

Responsibilities:

- Establish gRPC connection
- Invoke `ClassifyVideo`
- Return inference results to controllers

---

### `middleware`

Contains JWT authentication middleware protecting secured routes.

---

### `dbconfig`

Initializes and manages PostgreSQL database connectivity.

---

### `model`

Defines application data models used for database operations.

Current models include:

- User
- Deepfake Detection Result

---

### `routers`

Registers application routes and middleware.

---

### `utils`

Reusable helper functions including:

- Password hashing
- JSON parsing
- File storage utilities

---

### `roles`

Contains application role constants.

Current roles:

- User
- Admin (reserved for future implementation)

---

## Running the Service

The backend service is intended to run alongside:

- PostgreSQL
- Python ML inference service

Configuration is loaded through environment variables, and service orchestration is managed from the project's root using Docker Compose.
